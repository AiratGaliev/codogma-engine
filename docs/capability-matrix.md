# Матрица возможностей Codogma Engine

**Baseline:** legacy implementation baseline — `dev` commit `8cd494e0634d4b679fab62ca8379c39487395dd9` (30.10.2026). Новый Host evidence — `feat/cod-80-solidjs-editor-host-20261101`, PR #30 (открыт, не смержен), CI Fast #425; кодовый commit `09a81e95e51c3402f72443d44cfa90c865c03b56`.  
**Метод:** статический аудит структуры/исходников и сопоставление с README, ТЗ, roadmap, CI и описанием PR #10. Это не построчная проверка всех legacy-файлов и не runtime/browser acceptance.

## Как читать статус

- **Есть в исходниках** — в репозитории обнаружены соответствующие модули/сценарии. Это не утверждение о полном end-to-end качестве.
- **Частично** — имеется часть workflow или реализация, но отсутствует согласованный контракт/интеграция либо покрытие основных сценариев.
- **Не подтверждено** — статическая реализация видна, но нет достаточных runtime/браузерных тестов.
- **Не реализовано** — целевая функция не обнаружена как законченная подсистема в текущем baseline.
- **Отложено** — сознательно не входит в первый сквозной сценарий.

## Приоритеты из матрицы

1. **P0 — интеграция и независимая приёмка первого SolidJS Host slice:** COD-80 / PR #30 и CODQA-18. Не считать PR/CI success подтверждением production cutover.
2. **P0 — runtime/security acceptance:** закрывать Box2D/FX/codegen/Asset Pack residuals и cross-platform filesystem security отдельными проверяемыми задачами. Сохранять loopback/local-only security boundaries.
3. **P1 — staged Host migration:** COD-82 координирует workflow inventory и перенос в SolidJS. Новые Colibri UI features не создавать.
4. **P1 — специализированные authoring workflows:** Docking (COD-83), Asset/Sprite (COD-86), Prefab (COD-8), User Components/TypeScript (COD-91), camera/coordinates/sorting (COD-41), 2D UI authoring (COD-43), Tilemap (COD-40), Physics (COD-42), Animation (COD-84), FX (COD-89), Spine (COD-90), Audio/Particles (COD-61), Atlas analyzer (COD-55), importer extensions (COD-59).
5. **P1 — Preview/Diagnostics/MCP:** Preview Host, live Inspector, EngineLogger и session-aware MCP SSE (COD-85); COD-80 Game View iframe не является полноценным Preview Host.
6. **P1 — независимая functional acceptance:** CODQA-18 принимает первый Host slice; CODQA-10/11/12/13/14/16 и CODQA-4 подтверждают только соответствующие перенесённые workflows. Done QA issues старого UI остаются историческим evidence.
7. **P1 — cutover/removal:** COD-87 переводит default `/editor/` на SolidJS с rollback window; COD-88 удаляет Colibri после inventory sign-off, consumer audit и license review.
8. **Отдельные engine streams:** Project Model/Core, HTML5 Build, Platform Services, Game QA MCP, Package Manager и Tauri развиваются по собственным зависимостям и acceptance, а не превращаются в UI migration prerequisites.

## Ограничения аудита и следующая актуализация

- Полный построчный review всех 1 298 TypeScript-файлов не выполнялся: в репозитории около 1 480 tracked files, из них приблизительно 1 350 в `source/editor/`; основной объём — унаследованный editor client.
- Детально проверялись документы/CI/manifests, текущие серверные файловые и MCP-потоки, security smoke, PR #10 и ключевые участки code generation/FX/Box2D/asset preview по заявленным изменениям.
- Для каждой строки со статусом «не подтверждено» обновлять состояние только после привязанного regression test, runtime fixture либо документированной browser acceptance. Не переводить её в «реализовано» по наличию UI, деклараций TypeScript или успешной компиляции.
- Матрица — живой документ: изменения возможностей должны обновлять evidence, acceptance checks и соответствующие пункты `docs/roadmap.md`.
