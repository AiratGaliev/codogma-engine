**Метод:** статический аудит исходников/документов плюс CI evidence конкретного head; не построчная проверка всех legacy-файлов. Наличие кода или зелёный CI не является runtime/browser acceptance.

## Как читать статус

- **Есть в исходниках** — в репозитории обнаружены соответствующие модули/сценарии. Это не утверждение о полном end-to-end качестве.
- **Частично** — имеется часть workflow или реализация, но отсутствует согласованный контракт/интеграция либо покрытие основных сценариев.
- **Не подтверждено** — статическая реализация видна, но нет достаточных runtime/браузерных тестов.
- **Не реализовано** — целевая функция не обнаружена как законченная подсистема в текущем baseline.
- **Отложено** — сознательно не входит в первый сквозной сценарий.

## Приоритеты из матрицы

1. **P0 — улучшить существующий редактор, не дожидаясь нового Core:** workbench/layout, визуальная система, icon registry, light/dark themes, ключевые Scene/Hierarchy/Inspector/Assets flows и точечные regression fixes.
2. **P0 — ввести проверяемый engineering loop для изменяемого кода:** clean install/build/typecheck, адресные tests, постепенные ESLint/Prettier checks и отчётный режим анализа legacy dependencies.
3. **P0 — принять runtime-функции PR #10 только после реальной проверки:** FX, Box2D, Asset Pack/import, serialization/codegen/Particle Emitter fixtures.
4. **P0 для соответствующих API/сервисов — закрыть security residuals:** pathname-based filesystem TOCTOU до расширения write paths; standalone mini-services остаются loopback-only, нужны service-level tests и запрет non-loopback exposure без auth/authorization.
5. **P1 — добавить новые Core/Project Model contracts и runtime adapter после начальной стабилизации UI/основных existing workflows либо отдельным независимым потоком.**
6. **P1 — Preview Host, live Inspector и независимая HTML5-сборка**, когда готовы нужные model/runtime contracts; не считать editor build сборкой игры.
7. **P2 — Platform Services, desktop shell, alternative runtime/backends и package ecosystem** после стабилизации соответствующих contracts и подтверждения спроса.

## Ограничения аудита и следующая актуализация

- Полный построчный review всех 1 298 TypeScript-файлов не выполнялся: в репозитории около 1 480 tracked files, из них приблизительно 1 350 в `source/editor/`; основной объём — унаследованный editor client.
- Детально проверялись документы/CI/manifests, текущие серверные файловые и MCP-потоки, security smoke, PR #10 и ключевые участки code generation/FX/Box2D/asset preview по заявленным изменениям.
- Для каждой строки со статусом «не подтверждено» обновлять состояние только после привязанного regression test, runtime fixture либо документированной browser acceptance. Не переводить её в «реализовано» по наличию UI, деклараций TypeScript или успешной компиляции.
- Матрица — живой документ: изменения возможностей должны обновлять evidence, acceptance checks и соответствующие пункты `docs/roadmap.md`.
- В PR #21 исправляется найденный дефект генерации polygon hull: b2ComputeHull должен получать фактическое количество вершин после разбора координат. Regression test проверяет generated code; runtime-приёмка Box2D остаётся обязательной.
