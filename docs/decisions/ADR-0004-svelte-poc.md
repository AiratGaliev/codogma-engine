# ADR-0004: Ограниченный Svelte PoC — оценка стоимости моста, а не миграция

**Статус:** принято (PoC завершён, выводы зафиксированы; миграция НЕ начата).

> **Историческая граница решения:** вывод «не начинать миграцию» относился к ограниченному эксперименту и отражает решение на его дату. Он больше не определяет целевой UI framework: последующее принятое решение — независимый SolidJS Editor Host, описанный в [ADR-0005](ADR-0005-solidjs-editor-host.md) и [плане миграции](../editor-ui-migration.md). Все результаты ниже относятся только к Svelte PoC в legacy Colibri; их нельзя переносить на SolidJS или считать доказательством производительности нового Host.
**Дата:** 28.10.2026
**Связанные документы:** [дорожная карта](../roadmap.md) (бэклог PR #10, п. «Ограниченный Svelte PoC»), [ADR-0001: архитектура Core](ADR-0001-core-architecture.md), [ADR-0002: TypeScript toolchain](ADR-0002-typescript-toolchain.md).

## Контекст

Бэклог PR #10 содержит пункт «Ограниченный Svelte PoC»: до принятия решения о будущем UI-стеке редактора нужно **измерить**, сколько стоит интеграция Svelte-компонента в colibri workbench, а не переписывать редактор. Полная миграция на Svelte явно вне рамок (запрещена ограничениями задачи); результат PoC — данные и решение «продолжать ли разговор», а не новый UI-стек.

Требования к PoC:

- один реальный компонент на Svelte 5, живущий внутри workbench рядом с обычными colibri-частями;
- мост только через публичные точки расширения colibri (Plugin, Part, события), без форков ядра;
- измеримый результат: размер бандла, стоимость mount, стоимость события selection end-to-end;
- воспроизводимость без изменения основного toolchain (tsc не умеет компилировать `.svelte`).

## Решение

### 1. Отдельный плагин `phasereditor2d.sveltepoc`, нулевое влияние на остальной редактор

PoC живёт в собственном плагине `source/editor/plugins/phasereditor2d.sveltepoc/`. Он регистрируется как обычный colibri Plugin и не вносит изменений в код других плагинов. Отключение PoC = удаление каталога плагина; миграция на новую версию Svelte не затрагивает чужой код.

### 2. Мост: colibri-события → императивный API компонента, компонент → колбэки `actions`

- **Workbench → панель:** `LiveBridge` слушает `eventSelectionChanged` активной части, `eventThemeChanged`, `eventProjectOpened` и вызывает экспортированные функции компонента (`setSelection`, `setTheme`, …). Компонент не знает о colibri-типах — только о примитивах (labels строками, theme-токены).
- **Панель → workbench:** компонент получает проп `actions` (focusOutline / selectAll / benchmark). Никаких прямых обращений из `.svelte` к глобальному colibri.
- Это та же граница, что требует ADR-0001 для Core/adapter: UI-фреймворк части не протекает в остальной редактор.

### 3. Двойной режим: live (workbench) и mock (standalone)

Компонент собирается один раз и работает в двух режимах: live-режим регистрирует часть «Svelte PoC» рядом с Inspector; mock-режим (`index.html`, без colibri) питается от mock-источника событий с тем же контрактом (selection/theme). Mock-режим позволяет измерять бандл и mount-стоимость изолированно и служит executable-спецификацией контракта моста.

### 4. Toolchain: изолированная сборка esbuild + Svelte 5, компилированный бандл коммитится

- `build/build.mjs` (Svelte 5 compiler + esbuild, собственные devDependencies в `build/`) компилирует `src/SceneStatsPanel.svelte` и бандлит с runtime в `_out/svelte-poc.js` (IIFE, ~70 kB minified).
- `tsc -b` редактора не умеет обрабатывать `.svelte`, поэтому **компилированный бандл коммитится** (исключение в `source/editor/.gitignore`); `build.mjs` воспроизводит его байт-в-байт. Промежуточный `src/compiled/*.svelte.js` регенерируется сборкой и не коммитится.
- Регрессионная страховка: тестовый bundle-loader читает `plugin.json` всех плагинов; PoC-бандл загружается в Node-тестах в mock-ветке (`window.colibri` отсутствует) — отсутствие бандла сломало бы все bundle-тесты на свежем клоне, что и закрепляет коммит артефакта.

### 5. Измерения (приняты как результат PoC)

- Размер стоимости интеграции: бандл 70.3 kB (minified, с Svelte runtime), mount — 1.9 ms.
- Пропускная способность моста: 1000 событий selection через **полный** workbench-путь (`Part.setSelection` с ко-слушателями Inspector, outline sync и refresh-цепочками) — 1000/1000 обновлений дошли до компонента, ~7.6 ms на событие. Стоимость создаёт не мост и не Svelte (обновление компонента микросекунды), а ко-слушатели workbench; Svelte-слой узким местом не является.
- Главная стоимость — не производительность, а дублирование UI-слоя: тема, parts, layout, provider-инфраструктура colibri не переиспользуются Svelte-компонентом автоматически.

## Последствия

- **Миграция на Svelte не начинается.** PoC показал, что технически мост дёшев, но ценность миграции не доказана: доминирующая стоимость — паритет инфраструктуры UI, а не рантайм-производительность.
- Результаты этого PoC относятся только к интеграции Svelte-компонента внутрь тогдашнего Colibri Workbench. Это архивное историческое решение; оно не направляет реализацию нового UI и не является архитектурным шаблоном для SolidJS Host. Текущее принятое решение — самостоятельное SolidJS приложение по ADR-0005 без постоянного Colibri bridge.
- Плагин PoC остаётся в дереве как executable-справка (живой пример интеграции и бенчмарк). Он не входит в product-сборку по умолчанию и может быть удалён без последствий для остальных плагинов.
- Стилевые обязательства PoC (html.dark/html.light, CSS-переменные темы) соответствуют текущей конвенции colibri и не требуют изменений ядра.
