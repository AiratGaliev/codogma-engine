## 1. Назначение и цели

**Codogma Engine** — среда разработки HTML5-игр на Phaser (сейчас 4.2.1): визуальный Scene Editor, Asset Pack Editor, Animations Editor, компиляция сцен в код, AI/MCP-интеграция.

Стратегическая цель: развить проект от «редактора» до **полноценного движка уровня Unity** — единый runtime + редактор + сборка под платформы + расширяемость третьими сторонами.

Стратегия достижения — **постепенная замена унаследованного каркаса своим** (strangler-fig): новый код живёт рядом со старым, старый удаляется по мере готовности замены.

## 2. Текущее состояние (as-is)

### 2.1. Архитектура

| Слой | Реализация | Объём |
|---|---|---|
| Сервер | `server/server.mjs` — Node.js, без npm-зависимостей | ~940 строк |
| Клиент-ядро | `source/editor/plugins/colibri` — workbench, плагинная система, UI-контролы, файловое io | ~176 TS-файлов |
| Функциональные плагины | `phasereditor2d.*`: scene, pack, ide, files, outline, spine и др. | основная масса кода |
| Рантайм-бандлы | Phaser 4.2.1 (dist + типы), spine, CodeMirror 5.66 | в `plugins/` |
| Мини-сервисы | `mini-services/phaser-editor-mcp` (мост MCP, node + ws), `mini-services/ai-chat` (LLM-прокси) | .mjs |
| CI | GitHub Actions: `ci.yml` (быстрые проверки на PR + валидация маршрутов веток), `e2e.yml` (MCP-интеграционные тесты на PR в `test`/`main`), `release.yml` (сборка + смоук + zip-артефакт на push в main) | `.github/`, `tests/mcp-e2e-test.mjs` |

Ключевые порты: редактор **3000**, MCP-мост **1902**, AI Chat **3031**.

### 2.2. Возможности (v1.0)

* Scene Editor, Prefabs, User Components, Asset Pack, Animations, Editable Tilemap (Tiled-совместимый, 8 MCP-инструментов), Box2D, Arcade Physics, 24 Phaser 4 Filter, Video, ParticleEmitter.
* Компилятор сцен → TypeScript-код, совместимый с Phaser 4 API.
* MCP-интеграция (официальный `@phaserjs/editor-mcp-server` + локальный мост) и AI Chat.
* Локальный сервер: файловый REST API, play mode, upload.

### 2.3. Инфраструктура разработки

* Ветки: `feat/*|fix/*|refactor/*|test/*|docs/*|chore/*` → `dev` → `test` → `main` (срочно — `hotfix/*` → `main`). CI валидирует маршруты.
* Все команды — npm (bun удалён из проекта).
* Node ≥ 22 (версия CI), локально разработка идёт на 24.

## 3. Целевая архитектура (to-be)

```
┌────────────────────────────────────────────────────────────┐
│ Codogma Engine (Tauri 2)                                   │
│                                                            │
│  UI-слой: Svelte 5 (runes)                                 │
│    • workbench: dockview-core (панели/вкладки/сериализация) │
│    • реестры: commands / views / menus / content-types     │
│    • редактор кода: CodeMirror 6                           │
│    • canvas-вьюхи (Scene Editor, палитры) — без фреймворка │
│                                                            │
│  Ядро: Rust (Tauri)                                        │
│    • файловые операции: tauri-plugin-fs + свои команды     │
│    • watch файлов проекта, нативные диалоги                │
│    • protocol handler: раздача файлов проекта (play mode)  │
│    • MCP-мост (axum + ws) и LLM-прокси (reqwest)           │
│    • tauri updater (Check for Updates)                     │
│                                                            │
│  Рантайм игр: Phaser 4 (без изменений)                     │
└────────────────────────────────────────────────────────────┘
```

Принципы:

1. **Компиляторы сцен/префабов и форматы файлов не переписываются без необходимости.** Совместимость `.scene` / `.assetPack` / `.components` с текущими версиями — обязательна.
2. **Canvas-мир Scene Editor переносится как есть** — он быстрый и не зависит от каркаса сильнее, чем через io-слой.
3. Замена производится **по одной подсистеме**: старое работает до полной готовности нового.
4. Веб-версия (браузер) остаётся второстепенной целью сборки: Svelte-клиент работает и в Tauri, и в браузере; Tauri-API изолируются за флагом.

## 4. Требования

### 4.1. Функциональные (по подсистемам)

| Подсистема | Требование |
|---|---|
| Редактор сцен | Полная текущая функциональность v1.0: сцены, префабы (в т.ч. вложенные), user components, tilemap, физика, фильтры, blended mode |
| Компиляция | Вывод TS-кода идентичной семантики; пользовательские секции (`START-USER-*`) сохраняются между компиляциями |
| Файловая система | Открытие произвольной папки проекта; отслеживание изменений (watcher → обновление дерева без ручного refresh) |
| Play mode | Запуск игры из редактора; в Tauri — через iframe webview + protocol handler |
| AI/MCP | Все текущие MCP-инструменты и AI Chat сохраняются; мост переезжает в Rust-ядро |
| Распространение | Один бинарник на ОС (Windows/macOS/Linux) без предустановленного Node |
| Обновления | Check for Updates + автообновление через tauri updater |
| Экспорт игр | Сборка готовой игры под web (и далее desktop/mobile) — фаза 5+ |

### 4.2. Нефункциональные

* Открытие проекта среднего размера (~1000 файлов) ≤ 3 с до готовности UI.
* Сцена с 500+ объектами: редактирование без просадок FPS; тормоза лечатся алгоритмами, а не сменой каркаса.
* Холодный старт приложения ≤ 2 с.
* Работоспособность при отсутствии сети (все функции, кроме AI и обновлений).

### 4.3. Совместимость

* Форматы файлов проекта — без breaking-изменений; миграции — только аддитивные.
* Существующие проекты Phaser Editor 2D v3 открываются как есть.

## 5. Ограничения

1. **Не переписывать то, что работает и не мешает** — приоритет замен: сервер → оболочка → мелкие вьюхи → сцена.
2. **Rust-код минимальный**: везде, где хватает плагинов Tauri и существующего TS, язык не менять.
3. Третья сторона в зависимостях (spine, CodeMirror, Phaser) не заменяется в рамках миграции.
4. Multiplayer, ECS-фреймворк, 3D — вне скоупа миграции (отдельные решения после фазы 5).

## 6. Критерии приёмки этапов

Каждая фаза roadmap считается завершённой, когда:

1. выполнены её критерии из [roadmap.md](roadmap.md);
2. CI зелёный на `main`;
3. документы (`CHANGELOG.MD`, этот ТЗ, roadmap) обновлены;
4. удалённый код не остаётся «мёртвым грузом» в дереве (за удалением следует правка README/BUILD.md).

## 7. Риски

| Риск | Митигация |
|---|---|
| Недооценка объёма переноса Scene Editor (сериализация и компилятор срощены с colibri-моделью) | Сцена переносится последней; до этого colibri живёт как зависимость |
| Rust-фреймворк меняется быстрее ожиданий | Фиксация версий Tauri/плагинов в CI; минимальный рукописный Rust |
| Регрессии совместимости форматов | Тесты компилятора на фикстурах `tests/workspace` перед каждой миграцией io/сериализации |
| Потеря лицензионной чистоты при копировании кода между слоями | Копирайт Arian сохраняется до полной перезаписи; аудит перед удалением строки из LICENSE |

## 8. Глоссарий

* **colibri** — унаследованное ядро редактора (workbench, плагины, io) из Phaser Editor 2D v3.
* **Strangler-fig** — стратегия миграции: новое растёт рядом со старым, старое удаляется по частям.
* **MCP** — Model Context Protocol, протокол инструментов для AI-агентов.
* **Editable Tilemap** — тайлмап, редактируемый прямо в редакторе и компилируемый в Tiled-JSON.
