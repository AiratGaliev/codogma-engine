# Дорожная карта: Codogma Engine

Путь от «редактора» (v1.0) к «движку уровня Unity». Стратегия — strangler-fig (см. [technical-specification.md](technical-specification.md), разд. 1, 3). Даты не фиксируются жёстко: одна команда, оценка в порядке величины (недели-кварталы), уточняется по факту завершения фаз.

---

## Фаза 0 — основа (выполнено, октябрь 2026)

- [x] Ребрендинг в Codogma Engine, лицензия MIT (две строки копирайта).
- [x] Собственный локальный сервер (`server.mjs`, ~940 строк) взамен закрытого официального.
- [x] Phaser 4.2.1: бандл, типы, адаптация FX/Point API, компилятор.
- [x] Функциональная база v5-parity: Editable Tilemap, Box2D, 24 фильтра, Video/ParticleEmitter, AI Chat + MCP.
- [x] Уход с bun: все мини-сервисы на чистом Node, npm-скрипты.
- [x] CI: маршрутизация веток, сборка, смоук-тест, release-артефакт; ветки `dev`/`test`/`main`.

**Критерий выхода:** ✅ CI зелёный, проект собирается и запускается командами из README.

## Фаза 1 — оболочка Tauri

**Цель:** десктоп-приложение без переписывания логики.

- [ ] Проект Tauri 2 (Windows первым; macOS/Linux — за флагом).
- [ ] `server.mjs` запускается как sidecar-процесс.
- [ ] Собранный редактор v1.0 открывается в webview, работает как в браузере.
- [ ] Нативные диалоги выбора папки/файла вместо браузерных.
- [ ] Иконка, имя, метаданные приложения; сборка `.exe` локально и в CI.

**Критерии приёмки:**
- [ ] Двойной клик по `.exe` → редактор открывается, открывает проект, компилирует сцену, запускает play mode.
- [ ] CI: сборка Tauri-артефакта на push в `main`.

**Оценка:** недели.

## Фаза 2 — Rust-ядро, смерть server.mjs

**Цель:** файловый слой в Rust, расстаться с Node-сервером.

- [ ] Файловый REST API → Tauri-команды (`tauri-plugin-fs` + свои): list/read/write/rename/delete/query.
- [ ] Watcher файлов проекта → события в UI.
- [ ] Protocol handler для раздачи файлов проекта (play mode, ассеты).
- [ ] MCP-мост и ai-chat: в Rust (axum + ws, reqwest) либо временно остаются sidecar/мини-сервисами.
- [ ] Upload (drag-and-drop файлов в проект) — через нативные диалоги/буфер.
- [ ] `server.mjs` удалён; sidecar удалён; README/BUILD.md переписаны.

**Критерии приёмки:**
- [ ] Все действия, возможные в v1.0, работают без Node-процессов.
- [ ] Приложение стартует без сети.
- [ ] Фикстуры `tests/workspace` открываются и компилируются без изменений.

**Оценка:** недели–месяц. Здесь же умирает ~940 строк `server.mjs`.

## Фаза 3 — Svelte-оболочка

**Цель:** новый workbench, colibri теряет UI-слой.

- [ ] Vite + Svelte 5 (TS) + dockview-core: панели, вкладки, сериализация layout.
- [ ] Реестры: commands / menus / views / preferences (типизированные, вместо `ExtensionRegistry`).
- [ ] Вьюхи по одной: Files tree → Inspector → Outline → Blocks → Start Page → Settings → диалоги.
- [ ] CodeMirror 6 вместо CM 5.66.
- [ ] Двойной рантайм: colibri-вьюхи и Svelte-вьюхи работают одновременно (переход по вьюхам).
- [ ] Веб-сборка Svelte-клиента сохраняется (браузер).

**Критерии приёмки:**
- [ ] Каждый перенос вьюхи не ухудшает функциональность v1.0 (чек-лист по вьюхе).
- [ ] Производительность деревьев/панелей не хуже текущей (замер на проекте-фикстуре).

**Оценка:** месяцы (вьюх много, но они независимы).

## Фаза 4 — Scene Editor, смерть colibri

**Цель:** последний и самый сложный перенос; полное удаление унаследованного ядра.

- [ ] Слои сцены, инспекторы объектов, tools (select/translate/…), палитра тайлмапа — Svelte-обёртки над существующими canvas-компонентами.
- [ ] Сериализация/компилятор отвязываются от colibri-моделей (остаются прежними по формату).
- [ ] Animations Editor, Asset Pack Editor, User Components Editor — на новую оболочку.
- [ ] colibri и все его упоминания удалены из дерева исходников.
- [ ] Аудит остатков унаследованного кода → из `LICENSE` убирается копирайт Arian Fornaris (остаётся только Airat Galiev), README/AboutDialog переписаны.

**Критерии приёмки:**
- [ ] Полный цикл: создать проект → сцены/префабы/tilemap → компиляция → play → сохранение/переоткрытие — без изменений формата относительно v1.0.
- [ ] В исходниках не осталось файлов, производных от Phaser Editor 2D v3 (документированный аудит).

**Оценка:** месяцы. Самая рискованная фаза — см. риски в ТЗ.

## Фаза 5+ — движок уровня Unity (направления, требуют проработки)

Порядок и состав фазы уточняется по итогам фазы 4; зафиксированы направления, а не список фич:

- **Экспорт игр:** сборка web-билда в архив/папку одним действием; далее — desktop (через Tauri-шаблон игры) и мобильные.
- **Ассет-конвейер:** импорт/реимпорт, кэш, варианты сжатия текстур (задел уже есть — compressed textures UI).
- **Профилировщик и отладчик:** FPS/память в play mode, breakpoints по сценам.
- **Расширяемость:** SDK плагинов третьих сторон (документированные API реестров), маркетплейс/шаблоны.
- **Runtime-абстракция:** возможность подключать рантаймы кроме Phaser (решение — после стабилизации экспорта).

## Принципы ведения roadmap

1. Фаза не закрывается частично: критерии приёмки — целиком.
2. Каждая фаза заканчивается коммитом в `CHANGELOG.MD` и актуализацией этого файла (сдвиг галочек).
3. Удаление кода — в той же фазе, что и замена: мёртвый код не перевозим.
4. Новые идеи вне фаз записываются в Фазу 5+, не разбрасываются по тексту.
