# Каталог технических источников Codogma Engine

**Дата обновления каталога:** 02.11.2026  
**Даты проверки источников:** продуктовые руководства — 01.11.2026; Godot Editor source — 02.11.2026, commit `95c0fa5fe8a019adc29d074c16b64469b04571f7`.  
**Назначение:** быстрые ссылки на документацию и исходники, используемые при принятии архитектурных решений по ТЗ и roadmap.

Этот документ — индекс reference-материалов, а не список зависимостей к установке. Для пользовательского UX и 2D authoring единственного Editor Host нормативным является [Стандарт reference для 2D Editor Host](editor-reference-standard.md). Основные продуктовые референсы — Unity 6.6 (6000.6, Beta на дату проверки) и Cocos Creator 4.0 LTS; рассматриваются только 2D workflows. Детальный каталог полноценных открытых редакторов и инженерных паттернов ведётся отдельно в [Editor Engineering References](editor-engineering-references.md); он расширяет архитектурный контекст, но не меняет product UX baseline. **Godot Engine source** — отдельный implementation/engineering reference для изучения открытой реализации editor-подсистем, но не третий product/UX reference и не зависимость Codogma. Его revision закреплён в [стандарте](editor-reference-standard.md). Native Host и Core используют свои package roots и TypeScript toolchains; точные версии зафиксированы в package manifests/lockfiles и ADR-0002. Перед реализацией конкретной задачи перепроверь версию API, дату документации, совместимость с текущим Phaser runtime target, лицензию и зависимые лицензии. Запись в каталоге не означает, что библиотека выбрана или функциональность Codogma уже реализована.

**Критические различия версий:** руководство Creator 4.0 и отдельный исходный репозиторий cocos/cocos4 — разные reference-источники, не взаимозаменяемые API. Официальный Cocos Creator 4.0 User Manual обозначен как LTS; не смешивать его инструкции/API с Creator 3.x или отдельным исходным репозиторием. Официальная страница Unity 6.6 (6000.6) на 01.11.2026 обозначает эту версию как Beta, а не stable/Current. Поэтому Unity 6.6 остаётся главным UX-reference по требованию проекта, но Beta-only API/features нельзя считать стабильным техническим baseline; для технических решений отдельно сверять подходящую стабильную/LTS документацию Unity. Для внешнего кода фиксировать commit/tag, лицензию и upstream notices.
